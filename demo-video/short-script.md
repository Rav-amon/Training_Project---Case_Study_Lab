# Triage AI — сценарий короткого демо

## 1. Triage AI: запрос → ответ → база

Это короткая демонстрация проекта Triage AI. Сервис принимает обращение поддержки, классифицирует его языковой моделью, готовит черновик ответа и сохраняет полный результат в SQLite. Сейчас покажу всю цепочку на реальном запущенном приложении.

## 2. Один запрос проходит пять шагов

Клиент вызывает POST triage. FastAPI проверяет обязательные поля и допустимый канал, затем применяет лимит по client id. После этого текст уходит в OpenAI. Ответ модели снова проверяется: категория, уверенность, черновик и флаг эскалации должны соответствовать контракту. В конце результат записывается в таблицу tickets, а короткое событие — в лог.

## 3. API действительно запущен

На экране реальный Swagger запущенного FastAPI. Видны два маршрута: GET health для проверки состояния и POST triage для обработки обращения. Swagger формируется из кода автоматически и одновременно показывает фактический контракт сервиса.

## 4. Запрос и ответ модели

Отправляю обращение: не пришёл чек об оплате заказа две тысячи сорок восемь, канал email, клиент demo video. Сервер отвечает кодом двести. Категория — billing, уверенность — high, эскалация не требуется. В draft reply находится черновик ответа клиенту. На экране сохранён фактический curl, адрес запроса и JSON-ответ Swagger.

## 5. Та же обработка записана в SQLite

Сразу после ответа читаю таблицу tickets из data triage db. Найдена строка с номером семнадцать и тем же client id. В ней совпадают канал email, исходный текст, категория billing, уверенность high и черновик. Поле error равно null — обработка завершилась без ошибки. Это доказывает, что история не существует только в ответе API, а сохраняется в базе.

## 6. Лог подтверждает безопасную обработку

В терминале uvicorn появилось структурное JSON-событие с тем же client id, категорией billing и признаком ошибки false. Рядом виден POST triage с кодом двести. Текст обращения и ключ API в лог не попадают. Если модель сломается, сервис вернёт безопасный шаблон с escalate true и сохранит причину в error. Полная цепочка запроса, ответа, базы и лога подтверждена.
